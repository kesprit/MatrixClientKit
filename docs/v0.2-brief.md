# MatrixClientKit 0.2.0 — brief

## Contexte

MatrixClientKit (`https://github.com/kesprit/MatrixClientKit`, local : `Workspaces/Swift/MatrixClientKit`)
est un package Swift public qui enveloppe le Matrix Rust SDK derrière une API Swift 6. Dernière
version publiée : **0.1.1**. Amont épinglé : `matrix-rust-components-swift` `26.09.07`.

À lire avant de commencer :
- `docs/superpowers/specs/2026-09-13-matrixclientkit-design.md` — la spec, qui fait autorité (§6 API, §7 erreurs, §8 stockage, §12 paliers) ;
- `CONTRIBUTING.md` — règles d'architecture ;
- `Tests/MatrixClientKitIntegrationTests/README.md` — la suite d'intégration.

## Objectif

Rendre le chiffrement de bout en bout **pilotable** par une application : vérifier un appareil,
sauvegarder et récupérer ses clés, observer l'état du chiffrement. Plus quelques manques d'ergonomie
et de testabilité relevés à l'usage.

## Contenu

### 1. Chiffrement — le cœur de la version

Un service `encryption` sur `MatrixSession`, comme prévu par la spec (§6.1). Amont : `Client.encryption()`
et `Client.getSessionVerificationController()`.

- **États observables** — vérification, sauvegarde, récupération — exposés en flux d'**instantanés**
  (`.bufferingNewest(1)`) via le pont `ffiStream` existant. Amont : `verificationStateListener`,
  `backupStateListener`, `recoveryStateListener`.
- **Vérification d'appareil par SAS (emoji)** : demander la vérification de son propre appareil,
  recevoir une demande entrante, accepter, démarrer SAS, exposer les emojis, approuver, refuser,
  annuler. Amont : `SessionVerificationController` et son delegate à 7 callbacks — à convertir en
  flux d'événements plutôt qu'en delegate exposé.
- **Récupération** : activer (renvoie la clé à montrer à l'utilisateur), récupérer avec une clé,
  réinitialiser la clé, désactiver. Amont : `enableRecovery`, `recover`, `resetRecoveryKey`,
  `disableRecovery`.
- **Sauvegarde** : activer. Amont : `enableBackups`.
- **Aide à l'interface** : `isLastDevice` et `hasDevicesToVerifyAgainst`, qui décident de ce qu'un
  écran propose (vérifier contre un autre appareil ou passer par la clé de récupération).

**Vérification par QR : hors 0.2.** Les bindings épinglés ne l'exposent pas — les API QR présentes
servent à la *connexion* par QR, pas à la vérification. Ne pas l'implémenter à partir de ces API.
La spec la promet : la corriger en conséquence.

### 2. Session

- **Restaurer une session sans connaître l'URL du homeserver.** Aujourd'hui `Matrix.client(homeserver:)`
  exige l'URL avant `restoreSession()`, alors que l'URL est déjà persistée — une application doit la
  stocker une seconde fois, deux sources de vérité qui peuvent diverger. Fournir un point d'entrée qui
  restaure depuis le seul `MatrixStorage`.
- **Signaler une déconnexion côté serveur.** Brancher `ClientDelegate.didReceiveAuthError(isSoftLogout:)`
  et l'exposer publiquement (flux d'événements d'authentification), pour qu'une application sache
  qu'elle a été déconnectée pendant qu'elle tournait.
- **`SyncController.start()` : garantir et documenter l'idempotence.** Un double appel ne doit pas
  doubler l'abonnement à la sync. Vérifier le comportement réel, le rendre idempotent si besoin, le
  documenter dans le commentaire de doc.

### 3. Mocks (`MatrixClientKitMocks`)

- **`MockMatrixClient`** — il manque ; une application ne peut pas tester sa connexion sans en écrire un.
- **`MockTimeline`** : séparer `sendError` en une erreur d'envoi et une erreur de pagination. Aujourd'hui
  une seule propriété fait échouer les deux, rendant impossible un test « la pagination échoue, l'envoi
  réussit ». **Changement cassant** : le noter au CHANGELOG.
- **`MockMatrixSession`** : permettre de faire échouer `logout()` (injection d'erreur).
- **Mock du nouveau service de chiffrement**, pilotable comme les autres (`emit` / `finish` sur ses flux).
- **`SampleData.roomSummary(membership:)`** est déjà sur `main` mais jamais publié. Le publier, et
  **déclarer au CHANGELOG** que le paramètre est ajouté et que les fixtures « Salon » sont devenues
  « Lounge » — le commit qui l'a introduit était étiqueté à tort `docs:`.

### 4. Documentation

- README : mettre à jour la section Scope et la feuille de route (QR retiré de la 0.2).
- README : une ligne recommandant de s'appuyer sur `MatrixError.isRetryable` plutôt que d'écrire son
  propre mappage — c'est lui qui évite de proposer « réessayer » sur un échec TLS ou un quota dépassé.
- DocC : un article sur la vérification et la récupération, et les nouveaux types dans les Topics.
- Tout ce qui est destiné aux consommateurs est **en anglais**.

## Contraintes non négociables

- `MatrixClientKitCore` n'importe **jamais** `MatrixRustSDK`. Aucun type amont dans une signature `public`.
- Aucun `@MainActor` dans Core ni Rust. Types publics `Sendable`. Swift 6 strict.
- Flux de diffs en `.unbounded`, flux d'instantanés en `.bufferingNewest(1)`.
- **Erreurs** : les cas de `MatrixError` sont figés (voir README, « the evolution rule »). Utiliser les cas
  existants quand ils conviennent — `.encryption(.invalidRecoveryKey)` et `.encryption(.verificationRequired)`
  existent déjà. Tout nouveau cas, même dans un enum imbriqué, est un changement cassant : décision
  explicite, consignée au CHANGELOG.
- TDD, Swift Testing uniquement. `swift test --skip MatrixClientKitIntegrationTests` vert,
  `swift format lint --recursive --strict Sources Tests` propre, CI verte (build iOS compris).
- **Type de commit fidèle au contenu** : un commit qui change une API publique n'est jamais un `docs:`.
- Si l'amont doit être monté de version pour obtenir une API, relancer la suite d'intégration **avant**
  de publier. Elle a déjà attrapé trois défauts qu'aucun test unitaire ne voyait.
